Claude Code从入门到入土

Agent teams最佳实践

  1. 先定义接口
  2. Team Leader使用能力强的模型，teammets使用能力弱一点的模型
  3. 不同的teammets负责不同的文件，防止多个成员同时修改同一个文件导致合并冲突
  4. 不要让成员直接开始编码，先让他们研究和设计方案
  5. /tasks可以查看所有任务的状态

适合Agent Teams的场景

  1. 复杂系统重构
  2. 多角度代码审查
  3. 前后端并行开发

如何在不同成员之间切换

  1. shift+up 切换到上一个成员
  2. shift+down 切换到下一个成员
  3. shift+o 回到Team Lead

Claude Code + Superpowers

Superpowers用于让AI写出“工程级”的代码，而不是“玩具级”的代码，强调它遵循完整的软件开发流程

Superpowers完整工作流程

  1. Brainstorming(头脑风暴) 通过问答澄清真实需求
  2. Design Plans(编写计划) 分解为2-5分钟的小任务
  3. Subagent Development(子代理开发) 每个任务启动独立子代理；两阶段审查：规格符合性+代码质量
  4. TDD(测试驱动开发) 强制RED-GREEN-REFACTOR
  5. Code Review(代码审查) 质量把关

Claude Code工作流最佳实践

不同类型的项目，开发方式和ai使用策略也不同。选择合适的策略可以大大提高开发效率

全新项目

  1. 规划项目结构（推荐合适的技术栈、设计项目目录结构、规划数据库表结构）
  2. 搭建基础框架（创建项目目录、初始化配置文件、搭建基础的服务器代码【启动脚本、Dockerfile】）
  3. 逐个实现功能

成熟项目

  1. 了解项目结构
  2. 找到参考代码
  3. 模型现有风格来实现新的功能

维护项目

  1. 定位问题（找到相关的代码、分析可能的原因）
  2. 分析根因（看看这个错误在什么情况下产生）
  3. 实施修复

Claude.md的维护

  1. /init初始化Claude.md
  2. 在.claude/rules目录创建多个规则文件
  1. Claude.md的AI进化机制
    在项目开发的过程中，迭代claude.md
  2. 使用git管理claude.md

高级功能

plan模式

plan模式是一种先规划后执行的工作模式，当遇到复杂功能开发、架构重构、性能优化、代码迁移、不熟悉的项目的时候适合使用此模式
按两次shift+table进入plan模式

Headless模式

Headless模式是非交互式运行方式，输出结构直接输出标准输出，可集成到shell脚本或CI/CD流程中。
