线程池核心参数有哪些

1、核心线程大小：线程池一致运行，核心线程就不会停止
2、线程大小：线程池最大线程数量，线程池中非核心线程数量等于线程池中最大线程数量减去核心线程数量
3、非核心线程的存活时间：非核心线程在这个存活时间内没有运行任务，则会消亡
4、存活时间的计量单位
5、任务队列：用来存放线程任务
6、饱和策略：当线程池中线程数量等于线程池的最大线程数量且任务队列满了，将会执行饱和策略。有四种：线程任务丢弃报错；线程任务丢弃不报错；任务队列中首任务丢弃，最新线程任务入队；线程池外的线程直接调用run方法执行
7、线程工厂，新建一个线程时所使用到的工厂

当线程池收到一个任务，线程池中的线程数量是如何变化的

执行execute/submit方法向线程池中*添加任务，当任务数小于线程池中的核心线程数量，创建线程执行任务。当任务数大于最大核心线程数但小于最大线程数，会将任务放入阻塞队列中。如果阻塞队列满了，会新建非核心线程来运行任务。如果任务数量等于了最大线程数，会运用饱和策略中的策略。

ADD和COPY的区别是什么

COPY：简单直接，只做一件事
COPY 指令功能非常单一，就是将构建上下文中的文件或目录，原封不动地复制到镜像的指定路径。它不会对文件做任何额外处理。

ADD：功能更强，但有“魔法”
ADD 指令在 COPY 的基础上，多了两个容易造成困惑的“增强”功能：

自动解压压缩包：如果 ADD 的源文件是一个本地的压缩包（如 .tar.gz），它会自动将其解压到目标目录。这可能在你不希望解压时造成意外。
支持远程URL：ADD 可以直接从互联网URL下载文件并放入镜像。

docker构建上下文是什么

构建镜像时，Docker 会将当前目录（构建上下文）的所有文件发送给 Docker 守护进程。

有什么办法避免不将当前目录中的某个文件发送给Docker守护进程

在目录中创建 .dockerignore
